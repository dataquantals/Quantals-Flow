# Deployment

QuantalFlow is two things, and they need different hosting:

| Piece | What it is | Needs |
|---|---|---|
| **Static site** | 85 pages generated by `npm run build` into `public/` | any static host (Vercel) |
| **API server** | `server/` — accounts, sessions, boards, project plans, Convex mirror, Edit with AI | Node ≥ 22.5 with a **persistent disk** (`data/app.db` is SQLite) |

Vercel only serves the static half. A Vercel deployment with no API host renders
every page, but sign-up, sign-in, `/dashboard`, the canvas and plan saving all
fail, because they talk to `/api/*`. **Environment variables alone do not change
that** — nothing on Vercel runs `server/` code.

## Environment variables

Copy `.env.example` to `.env.local` for local work; set the same names in your
host's dashboard for production. Only `deployKey` / `DEEPSEEK_API_KEY` are
secrets — never commit them.

| Variable | Where | Required | Purpose |
|---|---|---|---|
| `APP_ORIGIN` | API host | production | Exact browser origin allowed to POST. Must be the URL users see. |
| `PORT`, `HOST` | API host | no | Default `12000` / `0.0.0.0`. Most hosts inject `PORT`. |
| `DB_FILE` | API host | no | Defaults to `data/app.db`. Point at the mounted volume. |
| `CONVEX_URL` | API host | yes for sync | e.g. `https://<deployment>.convex.cloud` |
| `CONVEX_SITE_URL` | API host | yes for sync | e.g. `https://<deployment>.convex.site` |
| `CONVEX_DEPLOY_KEY` | API host | yes for sync | Write credential. **Secret.** |
| `CLERK_PUBLISHABLE_KEY` | API host | no | Enables the Clerk SSO buttons. |
| `CLERK_SECRET_KEY` | API host | no | Verifies Clerk sessions. **Secret.** |
| `CLERK_APP_ID` | API host | no | Clerk app identifier. |
| `DEEPSEEK_API_KEY` | API host | no | Enables *Edit with AI* / plan copilot. **Secret.** |
| `SEED_EMAIL`, `SEED_PASSWORD`, `SEED_NAME` | API host | no | Account created by `npm run seed`. |
| `API_ORIGIN` | **Vercel** | only for Option B | Absolute URL of the API host (no trailing slash). |

`CONVEX_URL` also accepts `NEXT_PUBLIC_CONVEX_URL`; the Clerk publishable key
also accepts `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` / `VITE_CLERK_PUBLISHABLE_KEY`.

## Option A — one Node host (simplest, everything works)

Render, Railway, Fly.io, a VPS — anything that runs a long-lived Node process
and can mount a disk.

```
Build:            npm install
Start:            node server/index.js      (or: npm start)
Health:           GET /api/auth/config   (200 with the Clerk/Convex keys it knows)
Disk mount:       /var/data   →   DB_FILE=/var/data/app.db
```

Set every API-host variable from the table above, with `APP_ORIGIN` equal to the
public URL of the service. No `API_ORIGIN` needed: that server also serves the
built pages from the repo root, so the deployment is a single URL.

Seed the first account once the disk is mounted:

```
npm run seed
```

## Option B — Vercel static + API on a Node host

Use this if you want Vercel for the pages and something else for the API.

1. Deploy the API first, following Option A. Give it a stable HTTPS URL,
   e.g. `https://quantals-flow-api.onrender.com`.
2. On the **API host**, set `APP_ORIGIN=https://<your-vercel-domain>` so the
   same-origin check accepts form posts coming through the proxy.
3. On **Vercel**, add one variable:

   ```
   API_ORIGIN=https://quantals-flow-api.onrender.com
   ```

   Redeploy so the function picks it up.

`api/[...path].js` is a serverless function that forwards `/api/*` to
`API_ORIGIN` and streams the response (including `Set-Cookie`) back. The browser
only ever sees the Vercel origin, so the `HttpOnly` session cookie keeps working
and no client code changes. Without `API_ORIGIN` the function returns `503` with
a message naming the missing variable.

What the Vercel build does:

```
npm run build:vercel
  → node src/tools/build.js          generates the 85 routes at the repo root
  → node scripts/assemble-public.mjs copies only the public site into public/
```

`public/` never contains `server/`, `src/`, `convex/`, `data/` or `.env*`.

### Vercel limits worth knowing

- **Request body limit is 4.5 MB** per function invocation. Project plans are
  capped at 4 MB by the server, avatars at 5 MB — an avatar between 4.5 and
  5 MB will be rejected by Vercel before it reaches the API.
- **`trailingSlash: true`** matches the site's `/pricing/` links and the
  sitemap. The API router matches paths exactly (`/api/auth/login`), so
  `/api/*` must reach the function without a trailing slash. Vercel does not
  apply the setting to serverless functions; if you ever see `/api/...` 404s,
  set it to `false`.
- **Canonical URLs** are hardcoded in `src/tools/build.js` as
  `SITE = 'https://quantalflow.com'` and baked into every page's
  `<link rel="canonical">`, `og:url` and `sitemap.xml`. Add that domain in
  Vercel, or change `SITE` before building from another domain.

## Convex

Convex is a **mirror**: SQLite is authoritative and every board/plan write is
projected into Convex for querying. If `CONVEX_DEPLOY_KEY` is missing the app
still works — writes succeed locally and the sync logs a warning.

Push functions and backfill after changing anything under `convex/`:

```
npm run convex:push
npm run convex:backfill
```

## Rotating secrets

`server/config.js`, `server/routes.js` and `assets/js/app.js` previously carried
default copies of the Convex deploy key and the DeepSeek key — the last one was
shipped to the browser. Those literals are gone; the values now come only from
the environment, and the browser no longer talks to DeepSeek directly. Anything
that was ever committed is in git history and must be treated as public:

1. Rotate the DeepSeek key in the DeepSeek dashboard.
2. Create a new Convex deploy key and delete the old one.
3. Update `.env.local`, the API host's environment, and Vercel.
